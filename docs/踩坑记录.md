## 1. 命令执行环境变量问题

### 问题描述

在 Tauri 应用开发中，我们发现 dev 环境和 build 环境之间存在 Path 环境变量的差异：

- **Build 环境**：使用系统默认的 Path 环境变量
- **Dev 环境**：继承自终端的环境变量，可以访问 `~/.bash_profile` 或 `~/.zshrc` 等配置文件中的环境变量

这种差异导致在正式打包的应用中无法访问在开发环境中可用的自定义环境变量。

### 解决方案

在程序启动时，通过 fnm 获取 Node.js 环境路径，并将其添加到系统环境变量中，确保在执行命令时能够找到正确的可执行文件。

### 核心代码实现

```rust
let command = app.shell().sidecar("fnm")?;
tauri::async_runtime::spawn(async move {
    let output = command
        .args(["env", "--json"])
        .output()
        .await
        .expect("Failed to get fnm output");

    if output.status.success() {
        let res: Value =
            serde_json::from_slice(&output.stdout).expect("Failed to parse fnm output");

        info!("fnm output: {res:#?}");

        let node_path = res["FNM_MULTISHELL_PATH"]
            .as_str()
            .expect("FNM_MULTISHELL_PATH not found in fnm output");
        let path = std::env::var("PATH").unwrap_or_default();
        std::env::set_var("PATH", format!("{node_path}/bin:{path}"));
    }
});
```

### 实现说明

1. 使用 `app.shell().sidecar("fnm")` 创建 fnm 命令实例
2. 异步执行 `fnm env --json` 命令获取环境信息
3. 解析返回的 JSON 数据，提取 `FNM_MULTISHELL_PATH` 路径
4. 将该路径添加到系统的 PATH 环境变量中
5. 确保后续命令执行时能够正确找到 Node.js 相关的可执行文件
